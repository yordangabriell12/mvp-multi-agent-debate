## Kenapa kamu lihat "Connection failed" tanpa penjelasan

Dua hal bertumpuk:

**1. Pesan aslinya tidak terbaca.** 9Router membungkus alasan di JSON bersarang:
```
{"error":{"message":"[openai/gpt-4o] [429]: {\"error\":{\"message\":\"You have
no credits remaining...\",\"code\":\"credit_balance_exhausted\"}} (reset after 2s)"}}
```
Dan yang bikin repot: **ada newline literal di dalam string JSON**, sehingga JSON-nya bahkan tidak valid. `JSON.parse` gagal total, jadi tidak ada yang bisa ditampilkan.

**2. Kegagalan ada di tingkat model, bukan provider.** Jadi "Test connection" memakai model **pertama** di daftar. Kalau model pertama itu `gpt-4o`, hasilnya selalu gagal walau key dan base URL benar.

## Perbaikan

### 🔍 Pesan gagal sekarang bisa dibaca

`src/lib/providerError.ts` membuka sarang JSON dan menormalkan whitespace lebih dulu supaya payload yang tidak valid pun bisa dibaca.

| | |
|---|---|
| **Sebelum** | `Failed. Connection failed` |
| **Sesudah** | `Failed. You have no credits remaining. Add credits to continue using the API at https://platform.openai.com/settings/organization/billing/.` |

Ditambah 11 test memakai payload 9Router **asli** sebagai kasus uji. Test itu sempat gagal dan mengungkap bahwa newline literal membuat JSON tidak valid — perbaikan saya awalnya tidak menangani itu.

### 📥 Tombol Fetch models

Memanggil `GET /models` provider dan mengisi daftar model otomatis. 9Router punya **26 model**, dan tidak ada satu pun yang perlu diketik manual.

- Model yang sudah ada tidak dihapus
- Aman ditekan berulang
- Kalau provider tidak punya `/models`, ada pesan jelas

> [!note] Kenapa harus lewat server
> Browser tidak bisa memanggil provider langsung karena tidak ada header CORS di `/models`. Jadi endpoint `/api/providers/models` yang meneruskan, memakai guard SSRF yang sama.

### 📊 Hasil tampil sebagai blok, bukan teks kecil

Hasilnya punya latar warna, `role="status"`, dan `aria-live="polite"`, jadi terbaca juga oleh pembaca layar.
