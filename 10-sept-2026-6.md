## Kenapa kamu lihat "Connection failed" tanpa penjelasan

Dua hal bertumpuk:

**1. Pesan aslinya tidak terbaca.** 9Router membungkus alasan di JSON bersarang:
```
{"error":{"message":"[openai/gpt-4o] [429]: {\"error\":{\"message\":\"You have
no credits remaining...\",\"code\":\"credit_balance_exhausted\"}} (reset after 2s)"}}
```
Dan yang bikin repot: **ada newline literal di dalam string JSON**, sehingga JSON-nya bahkan tidak valid. `JSON.parse` gagal total, jadi tidak ada yang bisa ditampilkan.

**2. Kegagalan ada di tingkat model, bukan provider.** Jadi "Test connection" memakai model **pertama** di daftar. Kalau model pertama itu `gpt-4o`, hasilnya selalu gagal walau key dan base URL benar.

## Perbaikan

### 🔍 Pesan gagal sekarang bisa dibaca

`src/lib/providerError.ts` membuka sarang JSON dan menormalkan whitespace lebih dulu supaya payload yang tidak valid pun bisa dibaca.

| | |
|---|---|
| **Sebelum** | `Failed. Connection failed` |
| **Sesudah** | `Failed. You have no credits remaining. Add credits to continue using the API at https://platform.openai.com/settings/organization/billing/.` |

Ditambah 11 test memakai payload 9Router **asli** sebagai kasus uji. Test itu sempat gagal dan mengungkap bahwa newline literal membuat JSON tidak valid: perbaikan saya awalnya tidak menangani itu.

### 📥 Tombol Fetch models

Memanggil `GET /models` provider dan mengisi daftar model otomatis. 9Router punya **26 model**, dan tidak ada satu pun yang perlu diketik manual.

- Model yang sudah ada tidak dihapus
- Aman ditekan berulang
- Kalau provider tidak punya `/models`, ada pesan jelas

> [!note] Kenapa harus lewat server
> Browser tidak bisa memanggil provider langsung karena tidak ada header CORS di `/models`. Jadi endpoint `/api/providers/models` yang meneruskan, memakai guard SSRF yang sama.

### 📊 Hasil tampil sebagai blok, bukan teks kecil

Hasilnya punya latar warna, `role="status"`, dan `aria-live="polite"`, jadi terbaca juga oleh pembaca layar.

## 🔎 Temuan yang lebih dalam: masalah aslinya bukan 9Router

Setelah 9Router diperiksa dan ternyata sehat, saya membaca **config aslimu yang tersinkron** di server. Isinya berbeda dari dugaan:

| Field | Nilai |
| --- | --- |
| Provider | **DeepSeek** |
| Base URL | `https://api.deepseek.com` |
| Model | `Deep-seek` |
| Agent | Maya, Aldo, Sinta, semuanya memakai provider itu |

Lalu saya uji ketiganya secara terpisah:

| Yang diuji | Hasil | Kesimpulan |
| --- | --- | --- |
| API key | `200`, daftar model terbaca | ✅ **valid** |
| Base URL | `200` | ✅ **valid** |
| Model `Deep-seek` | `400` | ❌ **nama model salah** |
| Model `deepseek-chat` | `200` | ✅ berfungsi |
| Model `deepseek-reasoner` | `200` | ✅ berfungsi |

Provider-nya mengatakan alasannya dengan gamblang:

```
The supported API model names are deepseek-flash, deepseek-v4-pro,
but you passed Deep-seek
```

> [!important] Jadi penyebab "failed connection error" adalah **nama model**, bukan koneksi
> `Deep-seek` bukan id model yang dikenal DeepSeek. Key dan base URL-nya tidak pernah bermasalah.

### Yang saya perbaiki di config-mu

| Sebelum | Sesudah |
| --- | --- |
| Model: `Deep-seek` | Model: `deepseek-chat`, `deepseek-reasoner`, `deepseek-flash`, `deepseek-v4-pro` |
| Agent: `Deep-seek` | Agent: `deepseek-chat` |
| Base URL: `https://api.deepseek.com` | `https://api.deepseek.com/v1` |
| Nama provider: `deepseek` | `DeepSeek` |

Config lama disimpan sebagai cadangan sebelum diubah.

### Verifikasi akhir

```
POST /api/chat  (provider DeepSeek, model deepseek-chat)
-> 0:"OK"     HTTP 200
```

> [!tip] Perbaikan pesan error tadi justru yang membuat ini ketemu
> Sebelum diperbaiki, kamu hanya melihat "Connection failed". Sesudah, provider berkata sendiri: *"The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed Deep-seek"*. Kalimat itu langsung menunjukkan apa yang harus diganti.

> [!note] Ini juga membuktikan sinkronisasi config berguna
> Config-mu bisa diperiksa dari server justru karena sinkronisasi yang kita bangun tadi. Kalau masih localStorage saja, tidak ada yang bisa dibaca dari luar.
