| Uji | Hasil |

- `/api/config` GET/PUT, di balik login yang sama
- **AES-256-GCM** untuk seluruh payload
- Penulisan **atomik** (tulis ke file sementara lalu `rename`), supaya crash di tengah tidak meninggalkan file terpotong
- Store diamati lewat `subscribe`, bukan memanggil modul sync, agar tidak ada impor melingkar
- Volume `vma-data` supaya data bertahan saat image di-rebuild

### 2. 🐛 Loop berhenti memanggil ulang semua agent

- Default `maxRounds` jadi **1**: hanya giliran pembuka. Multi-giliran tetap ada lewat preset mode
- Pilihan giliran tulisannya jelas: `1: answers only`, `2: one exchange`, `3: debate`, `5`, `10: max`. Tidak ada lagi "20" atau "Unlimited" tanpa keterangan
- Tiap giliran tambahan muncul pesan sistem: *"Round 2 of 3: agents respond to each other"*
- Jeda antar agent **1500ms + 500ms → 600ms + 300ms**, dan ikut kecepatan sesi

### 3. 🧠 Anti halu + anti slop

Dua blok aturan sama ditempel ke **kedua cabang prompt** (debat dan normal), dan dipakai juga oleh penulis ulang teks.

| Blok | Isi |
|---|---|
| **EVIDENCE DISCIPLINE** | Pisahkan pengetahuan dari dugaan. Dilarang mengarang angka/tanggal/nama/kutipan/sumber. Sebutkan apa yang perlu diukur kalau data tidak ada. Labeli dugaan |
| **WRITING RULES** | Tanpa pembuka basa-basi, tanpa em dash, daftar kata terlarang (seamless, revolutionary, unlock, synergy, dll), utamakan yang konkret |

## 🔒 Temuan keamanan yang masih terbuka

> [!danger] SSRF lewat nama service Docker
> Diverifikasi langsung dari dalam container:
> ```
> portainer            → 172.18.0.6
> nginx-proxy-manager  → 172.18.0.2
> fetch("http://portainer:9000/api/status")  →  HTTP 200
> ```
> `netGuard` memeriksa **string URL**. Hostname `portainer` bukan IP literal dan tidak ada di daftar blokir, jadi lolos. Setelah itu Docker DNS me-resolve ke IP privat dan koneksi terjadi.
>
> Ini **lebih berbahaya kalau browser dipasang**, karena agent bisa memotret panel admin dan menaruh hasilnya di jawaban. Perbaikannya: resolve DNS dulu, lalu periksa **IP hasil resolve**, bukan hanya URL. Ini bagian dari rencana browser.
